# omo-sci 真实 TUI 验收规范

这份规范用于长期执行“真实项目测试 -> 定位问题 -> 修复 -> 回归”的闭环。真实 TUI 测试补充自动化测试，不能替代自动化测试；反过来也一样。

## 四层验证

| 层级 | 目的 | 触发条件 | 通过标准 |
|---|---|---|---|
| L1 单元/类型 | 锁定确定性代码行为 | 每次代码改动 | `bun run typecheck`、`bun test` 全绿 |
| L2 安装/运行时冒烟 | 验证 CLI、模板和 OpenCode 插件实际接线 | 安装器、插件工具、版本变更 | 干净目录安装后，doctor 识别同版 runtime plugin；OpenCode 工具列表出现全部 `passport-*` |
| L3 固定 TUI 场景 | 比较模型行为、耗时和审计链 | agent prompt、模型矩阵、阶段流程变更 | 固定输入逐检查点通过，Passport/产物与界面陈述一致 |
| L4 探索性实测 | 发现固定脚本没想到的问题 | 每个候选发布版至少一次 | 真实用户完成一个有价值的工作片段，问题进入分级清单 |

## 固定基准案例 A

主题：成人 VV-ECMO 肝素启动时机与严重出血/血栓，单中心回顾性队列 180 例。

固定事实：

- 启动时间 0-24 小时，中位约 4 小时，约 30% 超过 6 小时
- 有精确的 ECMO 启动、首次肝素和结局时间
- ELSO 严重出血约 45 例；血栓或氧合器更换约 28 例
- 延迟抗凝常由基线出血风险驱动，存在适应证混杂和不朽时间偏倚

关键挑战：

1. Dubin 应先确认暴露变异和时间戳可用性，不应立即把问题包装成创新点。
2. Stage 0 快搜应在 3 分钟内停止，保留 3-5 个 PMID/DOI/NCT 和覆盖限制，不取全文。
3. 进入 Stage 1 必须真实调用 `passport-advance-stage`；工具不可用时必须停止，不能改 JSON 绕过。
4. 6 小时只能作为预设策略切点之一，不能用本中心中位数或肝素半衰期伪装成因果依据。
5. IRBer 应检查 estimand、grace period 内事件处理、time-varying Cox 是否回答“启动时机”，以及 45/28 个事件能否承受复杂模型。
6. 界面宣布完成的每份产物都必须存在、非空、登记 checksum；Passport schema 必须有效。

## 每轮记录指标

- 环境：omo-sci/OpenCode 版本、安装根目录、是否继承父目录、已连接 MCP、模型/provider
- 体验：首个有用回答耗时、Stage 0 总轮数、快搜耗时、Stage 1 检索耗时
- 成本：主会话与子会话上下文、工具调用数、明显重复查询数
- 证据：主对话保留的可验证 ID 数、错误/重复 ID、覆盖限制是否保留
- 科学性：PICO/estimand、偏倚识别、方法与事件数匹配、结论强度
- 状态：Passport 工具调用、schema、签核原话、风险数组、wisdom、产物 checksum
- 真实性：界面陈述与磁盘文件是否一致

## 问题分级

- P0：审计链失真、伪造产物/文献/状态、数据破坏、无法完成核心流程
- P1：科学结论可能被实质误导、关键证据丢失、快流程严重超时、重要体验阻塞
- P2：表达、排版、次要效率或不影响结论的交互问题

## 闭环规则

1. 先保存原始现场，不在失败项目上边修边覆盖证据。
2. 写出最小复现和预期行为，再改代码或提示词。
3. 能转为确定性断言的问题必须补 L1/L2 回归测试。
4. 修复后用同一输入重跑失败检查点；模型行为问题至少重跑两次，避免把随机波动误判为修复。
5. 每轮同步 `CHANGELOG.md`、`log.md`、`handoff.md`；未发布本地版使用 `x.y.z-local.YYYYMMDDHHmm`。
6. 只有 P0 清零、P1 有明确处置且 L1-L3 通过，才进入候选发布。

## 测试目录命名

使用 `YYYYMMDD-NN-topic`，例如 `20260719-00-vv-ecmo-timing`。每次重跑新建目录，不复用失败项目；运行记录写入 `docs/testing/runs/`，真实患者数据和私人笔记不进入仓库。
