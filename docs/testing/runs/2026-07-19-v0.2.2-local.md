## 问题

### P0 运行时插件未加载

`opencode.json` 声明了 `plugin: ["omo-sci"]`，但 Bun 全局链接的包没有进入 OpenCode 的 npm 插件缓存，运行时不存在 Passport 工具。Dubin 把 `passport-advance-stage` 当成 Bash 命令执行，失败后直接编辑 Passport，并口头宣布已进入 Stage 1。

手工记录使用了错误字段：`completed_at` 代替 `signed_at`，`risks_acknowledged` 写成字符串；没有 wisdom，形成虚假审计轨迹。

### P1 Stage 0 快搜过重

快速摸底耗时 6 分 37 秒，子会话上下文约 183K；执行了重复检索、去重、全文读取和额外验证流程。结果本身较好，但不符合 Stage 0 的交互预算。

Dubin 汇总保留了作者、年份和结论，却丢失 Pubmeder 返回的 PMID/PMCID。

### P1 研究蓝图内部矛盾

- 一处正确描述 clone-censor-weight 对 grace period 内事件的处理，另一处又要求主分析全部排除这些事件。
- time-varying “未启动 -> 已启动”暴露未明确 estimand，不能自动等价于“早期 vs 延迟启动策略”。
- 用本中心中位数和肝素半衰期为 6 小时切点背书，推理不足。
- 45/28 个事件却同时规划多套加权、竞争风险、亚组和七项敏感性分析，过拟合风险高。

### P1 文献矩阵可核查性

同一 PMID 36508210 被赋予两个不同文献身份；个别记录缺少 ID，研究类型分类不准确。Stage 1 深搜仍需独立引用校验，不能只看矩阵格式完整。
